## Key findings (severity: critical for the legacy update channel; info for current products)

1. The legacy upload-channel obfuscation is a repeating 20-byte XOR key, independently verified across the complete matching 4.0.19 RPM.
2. The official packages expose the legacy PHP update/authentication workflow and native i386 code without a live device.
3. No evidence establishes reuse of this scheme or its secrets in XWEB Pro or E3/SS.

## Details per finding

### Legacy XOR recovery

The encrypted and plaintext 4.0.19 RPMs are both 909,552 bytes. XOR produces this
20-byte repeating key:

`f9 f6 e4 e3 93 91 91 98 8c d1 c0 d5 c2 c9 8c 95 8f 91 8f 90`

Decryption is byte-identical to the official USB plaintext, SHA-256
`6c5dd2db2c2864cf0f90436ea55295f81b90779b80518200cefbc04081c0ccb7`.
Minor-version variants adjust the final key byte. The extractor validates the
complete gzip stream and newc cpio magic. Twenty-three RPMs pass;
`XWEB2009-patch-ru.0.i386.rpm` fails gzip validation and is not claimed as
decrypted. RPM signature checking is a separate control; XOR recovery does not
imply a signature forgery.

### Update and authentication code

- `extracted/XWEB2009_rootfs-4.0.0/var/www/html/Information/XwebUpdate.php:209`
  invokes `preinstallf9.sh` through `xjsyswrap` with a daily password from
  `xjpasswd`.
- `extracted/XWEB2009_V333-20090407/RPMS/preinstall.sh:315` imports the Dixell
  public key, then checks RPM signatures before installation.
- `extracted/XWEB2009_rootfs-4.0.0/var/www/html/service/access.php:194` contains
  hardcoded legacy administrator hashes and the daily-password path.
- `extracted/XWEB2009_rootfs-4.0.0/var/www/html/service/xwtool.php:14` contains
  a hardcoded legacy credential check and an authenticated command console.
- `extracted/XWEB2009_components/V333/usr/bin/xjsyswrap` is recovered native
  code. The original `xjpasswd` was separately recovered from the official 3.2
  installer under `extracted/XWEB3000V32_components/`.
- `extracted/XWEB2009_upload-4.0.19/preinstallf9.decrypted.sh` is the complete
  update-preparation script, recovered with a separate repeating 20-byte XOR
  key derived from its shell header. It contains the full package sequence and
  RPM signature-check logic.

These are legacy XWEB2009 findings. They are not claims about XWEB Pro, whose
publicly documented current web stack is Lighttpd and Lua rather than this PHP
application.

### Transfer test to XWEB Pro

Recovered legacy strings and XOR-derived candidates were tested against:

- `extracted/XWEB_PRO_x86_1.1.1/data`
- `extracted/XWEB_PRO_xw500d_1.12.1.update/rootfs`
- `extracted/XWEB_PRO_1.15.1/rootfs`

Seven AES/3DES and EVP_BytesToKey/PBKDF2 combinations per candidate produced
315 first-block operations and zero plaintext hits. Evidence:
`results/xweb-legacy-derived-probe.json`.

## Known-CVE regression notes

The nine E3/SS Frostbyte10 CVEs do not apply to this legacy package. The older
XWEB-500 CVE-2021-45420/45421 issues are also not asserted against XWEB2009
without product/version evidence.

## Notes / limitations

- No live device was contacted. Recovered password binaries were run only under
  qemu-i386 for bounded known-answer tests.
- The original `xjpasswd` was recovered from the official 3.2 installer and
  independently validated. The recovered patches are not a bootable base image.
- Legacy XWEB2009 cannot be upgraded directly to XWEB Pro. An upgrade-and-key-
  capture experiment requires an owned older XWEB Pro device or runnable image.
- Modern PHP CVEs cannot be applied without a PHP interpreter/version, and no
  XWEB Pro PHP stack has been established.

## Responsible disclosure status

No new submission has been made. This analysis uses official public downloads
and offline static processing only; the affected legacy generation is distinct
from the currently supported XWEB Pro line.
