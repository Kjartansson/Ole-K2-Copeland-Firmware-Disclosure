# 2.34F01 trailing-data comparison

The 2.34F01 containers append high-entropy data after the declared payload:
770 bytes on SS and 858 bytes on E3. Their lengths are exactly explained by
physical 1 KiB alignment:

```text
physical_post_header_size = round_up(declared_payload_size, 1024)
trailing_length = (-declared_payload_size) mod 1024
```

SS 2.34F01 has payload remainder 254 and 770 trailing bytes; E3 2.34F01 has
remainder 166 and 858 trailing bytes. Older payloads are already 1 KiB-aligned
and have zero trailing bytes. This relationship was independently rechecked on
2026-11-01. The natural interpretation is logical payload length followed by
physical padding, not an added signature or MAC segment.

Direct comparison still shows:

- Both declared payloads end six bytes into an 8-byte block. The first two
  trailing bytes complete that block; the remaining data contains 107 aligned
  blocks on E3 and 96 on SS.
- Every remaining aligned block is unique. Across arbitrary byte alignments,
  849 E3 and 761 SS consecutive 8-byte windows are all distinct, and there are
  zero common windows between products.
- The older shared terminal block `985aecbcb0d9ed8a` does not occur in either
  complete 2.34F01 file. Shared fill block `49b9f8397062e325` occurs only in the
  declared payloads, never in trailing data.
- No shared prefix (the first bytes differ).
- First 32 bytes on SS:
  `edbe661a6ccc5a5fdcaf2322756e6e45c731510e50f9315992db9e0fd1f2ad39`
- First 32 bytes on E3:
  `d5817e78e326ab495660979d130f2e4c37c170e1a969ebf30f55ccd86701a805`

The lack of repeated padding blocks is inconsistent with simple uniform
plaintext fill transformed by unchanged deterministic 8-byte ECB. It does not
exclude uniform plaintext under position-dependent processing, another mode, or
different keying. No common structure, plaintext marker, or shared key/check
value was found. A signature inside some bytes remains possible but is
unnecessary to explain their lengths and is unproven. There is no length-based
evidence that 2.34F01 added package authentication.

Updater analysis should distinguish declared payload length from padded
physical container length, final partial-block handling, output truncation, and
padding disposal. `analysis/CONTAINER-FORMAT.md` contains the older
decompression and DER checks.
