# E2 4.11F02 E3 system-updater analysis

- Source URL: https://media.copeland.com/564d5cb8-8251-48d9-a11b-b16d0019b93a/E2_4.11F02_Firmware_Update.pkg
- Package SHA-256: `7eadeba1bda5ba1991c0ae05be7bbeef4df9fc19b51fbd2120ded36761069f1a`
- Package size: 21,820,592 bytes

## Complete ELF recovery

An i386 VxWorks ELF begins at package offset `0x8d993e`. Section headers and the
string table validate an image size of 1,466,392 bytes. The trimmed output is
`extracted/E2_4.11F02/SysUpdt.embedded.elf`, SHA-256
`531376ef12a71f6ab31bbc1d6d9ce7e01dcae679bb82c61cad7dd71f9dee00a9`.

Build metadata identifies VxWorks 6.8, `pcPentium2`, and
`C:/code/E3sysUpdate/SystemUpdateImage`. This is therefore an E3 updater, not
merely an E2E-related code sample. Strings include `/ata00:2/SysUpdt.bin`,
`/ata00:2/SysUpdt.tmp`, `/ata00:2/e2_fw.pkg`, CpcPackage parsing, Crunch, and
Blowfish-related routines.

## Crypto findings

The updater uses the same general Blowfish schedule family as E2E. The key
schedule at `0x655970` uses signed key-byte loads, and `0x655910` implements the
corresponding block operation. The salt reference at virtual address `0x747832`
is `$tIkb?A68D+tl?2@KL_`, distinct from the E2E salt `kb?A68D+tl?2@KL_`.

The exact `$tI...` composition was tested against the documented SFUB targets:
732 candidates, 1,464 operations, zero hits
(`results/e2-4.11F02-e3-salt-probe.json`). No `SFUB` or `SFUB_update` string is
present, so an SFUB handler cannot be claimed from this artifact alone.

## Classic E2 gap test

The existing E2E-derived cipher candidates were also tested against the classic
E2 `extracted/E2_3.11F02/SysUpdt.tmp` target using ELF, gzip, RPM, SquashFS,
uImage, XML, and VxWorks structure checks. The run produced 346,422 operations
and four two-byte gzip-prefix candidates. All four failed full-stream gzip
validation. There are zero validated hits
(`results/e2-classic-sysupdt-related-probe.json`).

## CpcPackage and permuted-key analysis

The `CpcPackage` call chain uses XML, CRC, and Crunch routines; no direct
Blowfish call was found in that parser path. The separate encryption/EEPROM
subsystem at `0x654690` and `0x6555e0` transforms a 175-byte printable blob at
`0x768d20`: even-indexed bytes are reversed into even output positions while
odd bytes remain in place. A 57-byte bounded copy selects the first 56 permuted
bytes as the Blowfish key. The MAC string branch is not selected because the
combined string exceeds 56 bytes.

`tools/e3_permuted_blowfish_probe.py` recovers that key and validates the Python
model against the genuine key-setup function `0x655fc0` under bounded Unicorn
emulation. The emulated 56-byte key and all 18 P-array words match. The key has
SHA-256 `5ecf6990d6e5720f24539457618c7f91392c2d0f47cba839196b647740558446`.
Both primitive directions and block endian conventions were tested against the
seven documented SFUB targets and every block shared by at least two packages:
14,675 targets, 58,700 block operations, zero hits
(`results/e3-permuted-blowfish-probe.json`). This is a validated key recovery
for the updater's separate data-protection routine, not an SFUB decryption key.

## Package-validation and network review

A complete Ghidra decompilation is preserved at
`build/e2-sysupdt-decompiled.c`; its analysis log is
`results/e2-4.11f02-ghidra.log`.

- `FUN_0062c4b0` at `0x62c4b0` reads a 32-bit payload length and 16-bit CRC,
  requires length `< 0x100000`, checks short reads, verifies payload CRC16 via
  `FUN_00649800`, parses elements, and calls `FUN_0062e570` for per-element
  validation. Type-3 elements recurse through the same constructor. CRC16 is an
  integrity check, not package authentication; no signature, MAC, or keyed hash
  was found in this parser path.
- `FUN_00624d60` opens the fixed local path `/ata00:2/e2_fw.pkg` supplied by
  `FUN_006240b0`. `FUN_006246b0` independently processes `BX50W.pkg` or
  `www.pkg`, selected by `FUN_00624260`.
- The package schema includes `SourceFile`, `TargetPath`, and `TargetSystem`, so
  crafted packages are a relevant local/update-file attack surface. This does
  not by itself prove a remote arbitrary-write vulnerability.
- FTP, TFTP, SSH, HTTP, shell, and socket strings also occur in the statically
  linked VxWorks image. The reviewed update entry points do not accept a URL,
  hostname, socket, or network package source. No updater-owned network path to
  these package-processing functions was established; generic OS service strings
  are not reachability evidence.

## Limitations and next evidence

- No SFUB plaintext or key has been recovered from this ELF.
- PlayStation SELF/jailbreak tools do not apply to this already-plain i386
  VxWorks ELF. Function-level emulation is the transferable technique, not the
  Sony container format.
- Further generic CpcPackage emulation would not supply an SFUB key because the
  mapped parser path has no cipher call. Decisive new evidence remains an actual
  E3/SS runtime updater/rootfs or an authorized device image containing the
  SFUB decode path.
